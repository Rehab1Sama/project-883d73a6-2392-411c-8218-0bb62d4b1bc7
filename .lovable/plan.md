# استيراد المشروع + بناء بوابة الطالبة

## المرحلة 1: استيراد المشروع كما هو

نسخ كامل محتوى الملف المضغوط إلى هذا المشروع بدون أي تعديل على الكود الموجود:

- كل `src/` (المسارات، المكوّنات، الهوكس، الـ lib، تكامل Supabase، الأنماط والأصول)
- `supabase/migrations/`، `public/`، `scripts/`، ملفات الإعداد (`package.json`، `vite.config.ts`، `tsconfig.json`، `vercel.json`، `components.json`، `eslint`، `prettier`)
- استبدال ملفات القالب الفارغ الحالية (index الفارغة، `styles.css`، `router.tsx`، `__root.tsx`)
- تثبيت الحزم من `package.json` كما هي (بدون ترقية إصدارات)
- لا يتم نسخ أي بيانات git

الاتصال بقاعدة البيانات: نفس مشروع Supabase الحالي. تُضاف مفاتيح `.env` المرفوعة كأسرار للمشروع (`SUPABASE_URL`، `SUPABASE_PUBLISHABLE_KEY`، `SUPABASE_PROJECT_ID` ونظائرها بـ `VITE_`) بدون تغيير القيم، والنشر يبقى على Vercel كما هو.

## المرحلة 2: بوابة الطالبة

الوضع الحالي بعد الفحص: كل صفحات `_authenticated/app/$slug/*` واجهة إدارة فقط، ولا يوجد أي مسار للطالبة. كذلك جدول `students` لا يحتوي عمود `user_id`، أي لا يوجد حالياً ربط بين حساب الدخول وصف الطالبة — لذلك يلزم إضافته قبل بناء الصفحة.

### 2.1 قاعدة البيانات (migration جديدة)

- إضافة عمود `user_id uuid references auth.users(id)` إلى `students` مع فهرس فريد.
- سياسة RLS للقراءة الذاتية على `students`: `auth.uid() = user_id`.
- سياسات قراءة ذاتية على `progress_records` و`attendance` و`circle_students` و`circles` و`tracks` وأسماء المعلمة/المشرفة (`profiles` عبر `user_roles`) مقيدة بصف الطالبة المرتبطة بالمستخدمة.
- منح الصلاحيات المطلوبة (`GRANT SELECT ... TO authenticated`).
- لا يُمسّ أي سياسة قائمة للموظفات.

### 2.2 المسار والصفحة

- مسار جديد: `src/routes/_authenticated/student/$slug.tsx` (منفصل تماماً عن مسار `app/$slug` الإداري).
- بعد تسجيل الدخول: فحص دور المستخدمة من `user_roles`؛ إذا كان `student` تُوجَّه إلى بوابة الطالبة، وغير ذلك يبقى السلوك الحالي دون تغيير.
- محتوى الصفحة (قراءة فقط):
  - بطاقة تعريف: اسم الطالبة، اسم المقرأة، الحالة.
  - حلقتها ومسارها، مع اسم المعلمة واسم المشرفة (من `user_roles` + `profiles` المرتبطة بالحلقة/المسار).
  - إحصائيات الحضور: عدد أيام الحضور، الغياب، التأخر، ونسبة الحضور خلال الفترة.
  - مستوى التقدّم: مجموع المحفوظ/المراجَع، آخر السجلات (التاريخ، السورة والآيات، الملاحظات)، ورسم بياني بسيط للتقدّم الأسبوعي/الشهري.
- تصميم متوافق مع نفس هوية المشروع (AppShell/الثيم/العربية RTL) بدون تعديل مكوّنات مشتركة.


### تفاصيل تقنية

- القراءات عبر عميل Supabase في المتصفح تحت حماية RLS، أو عبر `createServerFn` مع `requireSupabaseAuth` عند الحاجة لقراءة على الخادم.
- لا استخدام لمفتاح service role في أي مسار للطالبة.
- ربط حساب الطالبة بصفّها (تعبئة `user_id`) يتم عبر دعوة/تأكيد لاحق؛ في هذه المرحلة تعرض الصفحة رسالة واضحة إذا لم يكن الحساب مرتبطاً بصف طالبة.
